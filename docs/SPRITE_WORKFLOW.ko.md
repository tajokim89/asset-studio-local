# 다른 게임에서 다시 사용하는 방법

이 저장소는 생성 도구와 작업 절차를 보관한다. 2026-10-03 요청에 따라 실험 이미지, GIF, 원본 프레임, 모델 가중치와 계정 인증정보는 보관 대상에서 제외한다. 삭제한 캐릭터는 다음 작업에서 새로 만들거나 사용자가 제공한 기준 이미지를 사용해야 한다.

## 실행과 연결

1. 저장소를 받고 Python 3.11 이상으로 가상환경을 만든다.
2. `python -m pip install -r requirements.txt`를 실행한다.
3. Codex CLI에서 `codex login`으로 본인 ChatGPT 계정에 로그인한다. 인증 파일을 저장소에 복사하지 않는다.
4. 로컬 ComfyUI를 실행한다. 기본 주소는 `http://127.0.0.1:8188`이다.
5. `python server.py`를 실행하고 `http://127.0.0.1:4184`를 연다.

설치 위치가 다르면 `ASSET_STUDIO_COMFY_ROOT`, `ASSET_STUDIO_COMFY_URL`, 필요 시 `ASSET_STUDIO_CODEX_COMMAND`를 설정한다. 구체적인 PC 경로는 프로젝트마다 지정한다.

이미지 생성은 `asset_studio/codex_image_provider.py`의 Codex ChatGPT 로그인 경로를 사용한다. 별도 Hermes 실행이나 API 키 복사를 기본 절차로 요구하지 않는다. 현재 어댑터는 참조 이미지 생성은 지원하지만 편집 마스크는 지원하지 않는다.

애니메이션은 `asset_studio/sprite_video_pipeline.py`의 로컬 H3/H3 Fast 경로를 사용한다. 설치할 노드와 모델 파일 이름은 해당 파일의 `REQUIRED_NODES`, `MODEL_FILES`, `TEXT_ENCODER`, `VIDEO_VAE`를 기준으로 확인한다. 모델 파일 자체는 Git에 넣지 않는다.

## 작업 순서

1. 캐릭터 기준 이미지 한 장에서 얼굴, 체형, 의상, 무기, 잡는 손을 먼저 확정한다.
2. 요청한 방향의 기본 이미지를 하나씩 만든다. 오른손/왼손은 캐릭터의 해부학적 방향으로 명시한다. 비대칭 장비는 단순 좌우 반전하지 않는다.
3. 방향 기본 이미지를 검수한 뒤 해당 이미지를 애니메이션의 기준으로 사용한다.
4. 기본 이미지 → 걷기 → 다음 요청 동작 순으로 진행한다. 승인되지 않은 동작을 한꺼번에 만들지 않는다.
5. 원본 영상 프레임을 보존하고, 움직임의 핵심 구간에서 출력 프레임을 선택한다. 복제한 프레임을 새로운 중간 자세라고 설명하지 않는다.
6. 게임용 GIF와 천천히 보는 검수용 GIF를 별도로 제공한다. 사용자가 링크를 원하면 개별 GIF 링크를 제공하고 ZIP으로 대체하지 않는다.
7. 채택된 결과만 게임에 연결한다. 생성 방식이나 그림 스타일을 바꾼 후보를 검수 없이 기존 게임에 덮어쓰지 않는다.

## 프레임 수와 속도

프레임 수, 애니메이션 재생 시간, 게임 이동 속도는 서로 다른 값이다.

| 용도 | 시작해 볼 출력 프레임 | 비고 |
|---|---:|---|
| 기본 원본 추출 | 25 | 앱 기본 출력. 최종 게임 프레임 수와 구분 |
| 걷기 | 8 | 실제 한 걸음 주기에서 추출 |
| 뛰기 | 8 | 이동 속도와 발동작 재생 속도를 따로 조정 |
| 공격 | 12 | 6장도 가능하지만 중간 동작이 급해질 수 있음 |
| 대기 | 25 | 작은 호흡 동작. 필요하면 별도로 줄임 |

예: 공격 12장 / 30fps는 0.4초다. 검수용은 같은 12장을 장당 150ms로 표시하면 1.8초다. 느린 미리보기를 만들었다고 게임의 공격 속도를 바꾸지 않는다.

H3는 생성 프레임 길이에 제한이 있다. 현재 2초 요청은 56프레임/24fps의 원본으로 맞춰질 수 있다. `metadata.json`의 실제 길이와 `sample_indices`를 확인한다.

## 재사용 가능한 추출 도구

```powershell
python scripts/export_sprite_animation.py --input C:\game\raw-frames --output C:\game\exports\attack --indices 0,7,9,11,18,20,21,23,39,41,44,55 --fps 30 --preview-ms 150 --remove-green
```

입력은 PNG 프레임 폴더 또는 GIF다. 출력은 선택 프레임 PNG, 스프라이트 시트, 게임용 GIF, 느린 GIF, 메타데이터다. `--indices`는 실제 원본에 맞춰 직접 고른다. `--count`의 균등 추출은 편의 기능이며 좋은 포즈나 자연스러운 반복을 보장하지 않는다.

`--remove-green`은 **초록색이 없는 캐릭터를 초록 배경에서 생성했을 때만** 사용한다. 녹색 피부·의상도 지워질 수 있다. 그 경우 다른 배경색이나 별도 마스크 처리를 선택하고 이 옵션은 사용하지 않는다.

## 검수 기준과 실험에서 확인한 한계

- 얼굴, 체형, 어깨 갑옷, 의상과 무기 디자인이 같은 캐릭터로 유지되는가?
- 두 손 무기는 같은 손이 계속 날 쪽을 잡는가? 팔과 손이 실제로 연결되는가?
- 무기가 갑자기 작아지거나, 자루가 휘거나, 손에서 떨어지지 않는가?
- 방향, 캐릭터 크기, 바닥 기준점이 튀거나 무기가 잘리지 않는가?
- 요청하지 않은 궤적, 바닥 효과, 섬광이 없는가?
- 투명 배경과 초록 잔여색을 모든 최종 프레임에서 확인했는가?

숫자 검사만으로 의미상 품질을 통과 처리하지 않는다. 원래 팔 방향이 잘못된 기준 포즈를 H3가 자동으로 고쳐 줄 것으로 기대하지 않는다.

H3의 `last_frame`, `MiniMaxH3AddGuide`를 이용한 시작·중간·끝 포즈 실험은 지정 자세를 더 잘 따르게 했지만, 무기와 의상 일관성을 완전히 해결하지 못했다. R2V는 별도 모델이 필요하다. 노드가 설치됐다는 사실만으로 가중치 호환성이나 품질을 보장하지 않는다.

6포즈 시트를 직접 생성해 특정 칸만 교체하는 방법도 시험했지만 사용자가 이전 영상 결과를 더 낫다고 평가했다. 이 방식을 검증된 기본값으로 채택하거나 사용자에게 알리지 않고 전환하지 않는다. 현재 권장 출발점은 기준 이미지 기반 H3 영상 + 실제 중간 프레임 추출 + 느린 GIF 검수다.

## 다음 채팅에 복사해서 요청하기

> 이 프로젝트의 asset-studio-local과 docs/SPRITE_WORKFLOW.ko.md를 읽고 게임 에셋을 만들어줘. 캐릭터는 [외형], 스타일은 [스타일], 무기는 [무기와 잡는 손]이야. 우선 [방향 목록]의 기본 이미지와 걷기만 하나씩 만들어줘. 기본 이미지부터 보여주고, 걷기는 8프레임 게임용 GIF와 장당 150ms 검수용 GIF를 개별 링크로 줘. 배경은 투명, 추가 이펙트는 없어야 해. 얼굴·장비·손 순서가 틀리면 통과라고 하지 말고 실패 이유를 알려줘. 생성 방식 변경이나 게임 반영은 후보 확인 후 진행해줘. 이미지·GIF는 Git에 올리지 말고 도구·설정만 커밋해줘.

추가 동작은 다음처럼 요청한다.

> 확정한 [캐릭터/방향 기준 이미지]로 [뛰기/대기/공격]만 추가해줘. 공격은 [세로베기 등], 출력은 12프레임, 게임용은 0.4초, 검수용은 1.8초로 해줘. 기존 캐릭터와 장비를 유지하고 하나씩 생성해줘. 최대 새 생성 요청 [N]회로 제한하고 각 시도의 결과를 기록해줘.

## 저장과 정리

Git에는 소스, 테스트, 프롬프트 예시, 설정 형식, 사용법을 보관한다. 모델, 인증정보, 실험 원본, GIF, PNG 시트, 빌드용 이미지 아카이브는 넣지 않는다. 삭제 전 코드 보관 상태와 삭제 범위를 확인하고, 다른 작업의 이미지나 모델 가중치를 포괄적으로 삭제하지 않는다.

`examples/sprite-playground/`는 입력 처리와 애니메이션 재생을 재사용하는 코드 예시다. 에셋은 포함되지 않는다. 새 게임의 프레임으로 스프라이트 시트를 준비하고 `sprites.example.json`을 참고해 `sprites.json`을 작성한 후 HTTP 서버에서 실행한다.
